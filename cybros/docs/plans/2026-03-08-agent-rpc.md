# Agent RPC Implementation Plan

> **Update 2026-03-09:** Transport binding, deployment registration, and run-draft semantics in this plan are superseded by `docs/plans/2026-03-09-agent-deployment-connection-design.md` and `docs/plans/2026-03-09-agent-deployment-connection.md`. Do not implement stdio as the only production transport or rely on `AgentHost` as a core domain model.

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Define and implement the first language-agnostic `agent_rpc` contract between Cybros and programmable agents.

**Architecture:** Keep the protocol schema-first and transport-neutral, with a real network transport for production deployments and stdio as a dev/test adapter. Treat methods as stateless and sessions as bounded to one lifecycle action or one turn. Separate canonical wire schemas from Ruby authoring helpers and avoid any requirement for Rails to hold permanent agent connections.

**Tech Stack:** Ruby on Rails, JSON Schema, WebSocket, stdio adapter, AgentDeployment, programmable agents

## Testing Posture

Every behavior-changing task in this plan should name exact verification files and commands.

- protocol-shape tasks should use schema or validator tests
- transport and runtime tasks should add integration coverage before merge
- the first user-visible programmable-agent flow should carry a Playwright E2E test, rather than forcing browser tests onto transport-only tasks
